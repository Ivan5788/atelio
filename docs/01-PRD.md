# Atelio 產品需求文件（PRD）

> 版本：v0.1（Phase 1）・最後更新：2026-11-19
> 狀態：規劃中。本文件中的「完成」皆指規劃完成，非實作完成。

---

## 1. 產品一句話

**Atelio 是一個讓人探索、比較並預約設計與手作工作坊的平台，同時提供開課者管理課程與查看報名數據的後台。**

> ⚠️ 資料誠信聲明：本作品為求職作品，平台上所有工作坊、講師、評價與報名數據皆為**虛構示範資料**，網站上會以明顯標示告知訪客，不會偽裝成真實開課資訊。

---

## 2. 為什麼是這個題材

| 面向 | 說明 |
| --- | --- |
| 商業合理性 | 體驗型課程市場（陶藝、皮革、花藝、版畫、字體設計）在台灣有明確需求，現有平台資訊分散、比較困難。 |
| 前端技術覆蓋 | 同時需要：列表搜尋／篩選／排序／分頁、詳細頁、多步驟表單、CRUD、會員狀態、後台圖表。 |
| 求職者背景契合 | 7 年平面設計經驗可直接轉化為視覺語言、排版與設計系統，面試時能說明「為什麼這樣設計」。 |
| SEO / GEO 價值 | 工作坊、講師、地點、知識文章都是搜尋引擎與 AI 搜尋願意引用的結構化資訊（Event、Course、Person、FAQPage）。 |
| 與既有作品區隔 | 不與股票儀表板、TeamHub、純 CRUD 作品重疊。 |

## 3. 目標使用者

### Persona A — 學員「小安」
- 28 歲，上班族，週末想找放鬆、能帶作品回家的體驗課。
- 痛點：課程資訊散在 IG 與各工作室官網，難以比較價格、地點、難度與剩餘名額。
- 目標：用最少步驟找到「這週末、台北、新手可上」的課並完成預約。

### Persona B — 開課者「阿哲」
- 35 歲，獨立陶藝工作室負責人。
- 痛點：用表單 + 私訊收報名，名額與場次難以管理，不知道哪堂課最受歡迎。
- 目標：上架課程、管理場次、看到報名趨勢。

### 次要使用者
- **搜尋引擎爬蟲 / AI 搜尋引擎**：需要能取得完整 HTML 與結構化資料（見 SEO、GEO 文件）。
- **面試官**：需在 3–5 分鐘內體驗完整流程，故提供「一鍵 Demo 登入」。

## 5. 非目標（本作品刻意不做）

- **真實金流**：預約僅模擬送出，不串接付款。
- **長期保存的正式帳號**：帳號機制是真的（密碼雜湊、加密 Session、授權檢查），但資料 72 小時後自動刪除，也不做 OAuth、忘記密碼與 Email 驗證。理由：求職作品不應長期保存訪客的個人資料，避免個資外洩責任。
- **即時通訊、通知推播**。
- **多語系**：僅繁體中文（URL slug 使用英文以利分享與 SEO）。

不做的理由：這些功能主要是後端責任，加入後會稀釋前端展示重點，且容易變成「看起來有、實際上是假的」。

## 6. 成功標準（可驗證）

| 項目 | 標準 | 驗證方式 |
| --- | --- | --- |
| 核心流程 | 訪客可完成「搜尋 → 詳細 → 預約 → 我的預約 → 取消」 | Playwright E2E |
| 後台流程 | 可完成「新增工作坊 → 編輯 → 下架 → 刪除」 | Playwright E2E |
| 可索引 HTML | 公開頁面在停用 JavaScript 時仍有完整主要內容 | `curl` 檢查原始 HTML、Rich Results Test |
| 效能 | 行動版 Lighthouse Performance 目標 ≥ 90（實測後如實記錄） | Lighthouse 報告存檔 |
| 無障礙 | Lighthouse Accessibility 目標 ≥ 95；全流程可僅用鍵盤完成 | Lighthouse + 手動測試 |
| 程式品質 | `lint`、`typecheck`、`test` 全數通過 | CI 指令 |

> 所有數據以實際執行結果為準，未達標會在開發紀錄中如實說明原因與改善方向。
